APPLICATION SETUP

One platform. Your apps.

Create a separate app identity, choose its permissions, then verify worker execution.

1. Create an application connection

Your backend must derive each external user ID from its signed-in user. An existing app keeps its current connection; creating a new one does not migrate its data.

Tool access

Select only the tools this app needs. The platform connection test makes no provider calls.

Application permissions

Sending actions still use the platform's approval rules. WhatsApp and calling also require the business's existing channel authorization.

Usage limits

These are request limits, not a rupee spending cap. Provider pricing and tool-specific limits still apply. Scheduled runs start disabled.

2. Check an app connection

The worker test verifies task execution without sending messages or calling paid providers. Model quality, business-tool results and callback receipt need separate live acceptance tests.

Choose how we provide your services

For the application selected above, choose our own service or a provider-backed option. We operate both through the same platform; your customer does not need a separate provider account.

Our service uses your platform plan and limits. Provider-backed options can add charges. Pricing must be confirmed before activation. WhatsApp number authorization and applicable Meta charges remain with either option.

3. Connect your app backend

  1. Load the saved private client file in your backend. Keep it out of frontend code and Git.
  2. Call /v1/integrations/task-readiness with the service credential and your signed-in user's ID.
  3. Create and run agents through /v1/task-agents. Poll tasks or use their event stream for progress.
  4. Confirm one real business task in your app before enabling it for customers.

Python and TypeScript connection-test examples are included under examples/integration/ in the platform repository.
